# ADR-0003 amendment (2026-07-31): Phase 4 publishing model confirmed

Status: Accepted

## Summary

Option 1 (platform-native MaaS) is confirmed viable through model
publishing. A model opts in to governance by referencing the MaaS gateway;
publishing auto-creates the gateway routing; a subscription reconciles
into an enforced Kuadrant TokenRateLimitPolicy. Deny-by-default is proven
(403 unauthenticated on a published model).

## Decisions

1. **Gateway access is controlled by namespace label.** The listener uses
   `allowedRoutes.namespaces.from: Selector` on
   `maas.opendatahub.io/publish=true` rather than `All`. Which teams may
   publish models under governance is itself a control. Both `maas-models`
   and `redhat-ods-applications` carry the label.
2. **No hostname on the listener in the lab.** Wildcard DNS points at the
   default router, not this gateway. Clients use the load balancer address
   and `curl -k`. A customer deployment adds a DNS record or DNSPolicy and
   a matching hostname; this is a lab constraint, not the pattern.
3. **The demonstration workload is Qwen3-0.6B**, co-tenanting the single
   L4 at a constrained GPU memory fraction. UC02's Granite keeps its
   direct path. Registering Granite through MaaS remains available (vLLM
   on MaaS is Technology Preview, gated by the `vLLMDeploymentOnMaaS`
   dashboard flag) and is the route to the governed-versus-direct
   comparison demo.

## Economics pillar evidence

`MaaSSubscription` carries `billingRate.perToken` and `tokenMetadata`
(`costCenter`, `organizationId`, labels) as first-class fields. A bank can
attribute token spend to a cost centre and organisational unit
declaratively, in Git, per subscription, with the limit enforced at the
gateway by the same object. This is stronger than the composed-gateway
alternative (option 2) could have achieved.

`ExternalModel` as a backend type means the same governance applies to
third-party providers. For ANZ, whose use case names Claude on Bedrock,
this makes the positioning concrete: keep the model where it is, put the
consumption behind the bank's control plane.

## Constraint recorded

GPU capacity allocation is not governed by MaaS. Token budgets control
consumption; two workloads sharing a card do so by mutual agreement on
memory fractions. Production requires MIG, time-slicing, or separate
hardware. This is a distinct control that needs its own answer in any
customer design.
